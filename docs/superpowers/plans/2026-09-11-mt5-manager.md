# MT5 Manager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a safe .NET 8 WPF desktop application that discovers and individually manages MT5 terminals and clears their Logs, Ticks, and History data.

**Architecture:** A WPF presentation project depends on a platform-neutral application/domain project; Windows process and filesystem adapters stay in an infrastructure project. Destructive operations pass through one coordinator that serializes work per terminal, verifies the terminal has exited, validates fixed allowlisted paths, records partial outcomes, and conditionally restores the prior running state.

**Tech Stack:** .NET 8, WPF, CommunityToolkit.Mvvm, Microsoft.Extensions.DependencyInjection, System.Text.Json, xUnit, FluentAssertions.

---

## Planned File Structure

- `src/Mt5Manager.Domain/Models/*.cs`: immutable terminal, process, storage, cleanup, and operation contracts.
- `src/Mt5Manager.Application/Abstractions/*.cs`: interfaces consumed by orchestration and UI.
- `src/Mt5Manager.Application/Services/TerminalOperationCoordinator.cs`: per-terminal lifecycle orchestration.
- `src/Mt5Manager.Infrastructure/Discovery/*.cs`: process, shortcut, standard-location, and manual discovery.
- `src/Mt5Manager.Infrastructure/Processes/WindowsTerminalProcessController.cs`: Windows start/close/kill behavior.
- `src/Mt5Manager.Infrastructure/Storage/*.cs`: safe target resolution, inspection, and deletion.
- `src/Mt5Manager.Infrastructure/Persistence/*.cs`: atomic JSON registry and append-only audit log.
- `src/Mt5Manager.Wpf/ViewModels/*.cs`: UI state and commands only.
- `src/Mt5Manager.Wpf/Views/*.xaml`: terminal list, registration dialog, cleanup dialog, force-kill prompt, and result presentation.
- `tests/*`: contract-focused unit and Windows integration tests using disposable directories/processes.
